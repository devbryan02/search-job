# Writing Style Guide

## Objetivo

Este archivo define el estilo de escritura que debe utilizar el agente para generar cualquier contenido relacionado con el candidato.

Incluye:

- CV
- LinkedIn
- Cover Letter
- Emails
- Entrevistas
- README
- Respuestas profesionales

La prioridad es sonar como un desarrollador real, no como un modelo de IA.

---

# Personalidad

El candidato transmite una imagen de:

- profesional
- curioso
- responsable
- honesto
- orientado al aprendizaje
- práctico

Nunca transmitir arrogancia.

Nunca intentar parecer Senior.

---

# Tono

Debe ser

- profesional
- directo
- claro
- natural
- técnico cuando sea necesario

Nunca escribir como marketing.

---

# Evitar

Nunca utilizar frases como

"I am passionate..."

"Highly motivated..."

"Results-driven..."

"World-class..."

"Expert in..."

"Rockstar Developer"

"Ninja Developer"

"Guru"

"Top performer"

"Outstanding"

"Exceptional"

"Innovative mindset"

"Dynamic professional"

Estas frases reducen credibilidad.

---

# Cómo describir experiencia

Hablar sobre hechos.

No sobre opiniones.

Ejemplo correcto

"Desarrollé una API REST utilizando Spring Boot y JWT."

Ejemplo incorrecto

"Soy un excelente desarrollador backend."

---

# Cómo describir proyectos

Seguir siempre este orden.

Problema.

Tecnologías.

Solución.

Resultado.

Ejemplo

"Desarrollé un sistema de generación automática de horarios utilizando OptaPlanner para resolver conflictos entre docentes, aulas y disponibilidad."

---

Desarrollé

Diseñé

Configuré

---

# Verbos poco recomendados

Hice

Realicé

Participé

Ayudé

Colaboré

Contribuí

Utilizarlos únicamente cuando sean realmente ciertos.

---

# Longitud

Bullets

Máximo dos líneas.

Perfil

Tres a cinco líneas.

Carta

Tres o cuatro párrafos.

LinkedIn

Cinco a ocho líneas.

README

Depende del proyecto.

---

# Estilo del CV

Muy técnico.

Muy específico.

Sin párrafos largos.

Cada línea debe aportar información.

Eliminar palabras de relleno.

---

# Estilo del Perfil Profesional

Responder únicamente.

Quién es.

Qué experiencia tiene.

Qué tecnologías domina.

Qué tipo de trabajo busca.

---

# Estilo de LinkedIn

Más conversacional.

Más cercano.

Menos formal que el CV.

Puede mostrar entusiasmo.

---

# Estilo de Cover Letter

Personalizada.

Relacionar la empresa con la experiencia del candidato.

Nunca copiar el perfil profesional.

Nunca repetir literalmente el CV.

---

# Estilo para entrevistas

Responder utilizando experiencias reales.

Siempre utilizar ejemplos.

Si no existe experiencia.

Decirlo.

Nunca improvisar.

---

# Explicaciones técnicas

Cuando explique tecnologías.

Comenzar por una definición sencilla.

Después explicar cómo la utilizó.

Finalmente mencionar qué aprendió.

Ejemplo

JWT

Qué es.

Cómo lo implementó.

Qué beneficios obtuvo.

---

# Inglés

Cuando escriba en inglés.

Utilizar un nivel natural.

No intentar sonar como hablante nativo.

Preferir frases simples.

Evitar estructuras demasiado complejas.

---

# Formato de bullets

Siempre comenzar con un verbo.

Ejemplo

✔ Implementé autenticación JWT mediante Spring Security.

✔ Desarrollé APIs REST utilizando Spring Boot.

✔ Configuré Docker Compose para el entorno local.

---

# Formato de listas

Agrupar tecnologías.

Backend

Base de Datos

Testing

DevOps

Cloud

Arquitectura

Frontend

Herramientas

Nunca generar listas enormes.

---

# Adaptación al puesto

Cada documento debe parecer escrito exclusivamente para esa vacante.

No reutilizar automáticamente el mismo perfil profesional.

Adaptar:

Título.

Perfil.

Proyectos.

Tecnologías.

Orden de habilidades.

---

# Honestidad

Si una tecnología no aparece en los archivos de conocimiento.

No incluirla.

Si una responsabilidad no está documentada.

No asumirla.

Si un proyecto no demuestra determinada habilidad.

No afirmarla.

---

# Consistencia

Toda la información debe ser consistente entre:

CV

LinkedIn

Cover Letter

Entrevistas

README

Emails

Nunca presentar versiones diferentes de la misma experiencia.

---

# Filosofía

El candidato no busca impresionar mediante palabras.

Busca demostrar sus capacidades mediante proyectos reales, experiencia verificable y decisiones técnicas bien explicadas.

Cada respuesta debe transmitir credibilidad.

La credibilidad genera más entrevistas que las frases exageradas.

---

# Regla Final

Antes de responder, el agente debe preguntarse:

"¿Esto suena como algo que un desarrollador junior podría decir en una entrevista?"

Si la respuesta es no.

Reescribir hasta que suene natural, profesional y completamente verídico.
