# ats.md

# ATS & Recruiter Intelligence

## Objetivo

Este archivo define cómo debe analizar una oferta laboral y cómo adaptar el CV para maximizar la probabilidad de obtener una entrevista.

El objetivo NO es engañar al ATS.

El objetivo es comunicar mejor la experiencia real del candidato utilizando el mismo lenguaje del anuncio.

Toda adaptación debe ser completamente verídica.

---

# Prioridades

Siempre seguir este orden.

1. Veracidad.
2. Relevancia.
3. Compatibilidad ATS.
4. Claridad.
5. Brevedad.

Nunca sacrificar la honestidad por aumentar el ATS Score.

---

# Flujo de análisis

Antes de modificar el CV analizar completamente la oferta.

Extraer:

- Cargo
- Empresa
- Industria
- Seniority
- Modalidad
- País
- Idioma
- Tecnologías obligatorias
- Tecnologías deseables
- Herramientas
- Frameworks
- Bases de datos
- Cloud
- Responsabilidades
- Soft Skills
- Palabras clave repetidas

---

# Clasificación de requisitos

Cada requisito debe clasificarse como:

## Cumplido

Existe experiencia demostrable.

Ejemplo

Spring Boot

Docker

JWT

Laravel

---

## Parcial

Existe experiencia relacionada.

Ejemplo

La oferta solicita Kubernetes.

El candidato posee Docker y Docker Compose.

No afirmar Kubernetes.

Simplemente priorizar Docker.

---

## No demostrado

No existe evidencia.

Ejemplo

Kafka.

Redis.

Terraform.

Azure.

Nunca agregarlos al CV.

---

# Reescritura ATS

Cada bullet debe cumplir al menos tres de estas condiciones.

- incluir una tecnología.
- describir una acción.
- explicar un resultado.
- utilizar un verbo fuerte.
- ser específico.

Ejemplo malo

Trabajé con Java.

Ejemplo bueno

Desarrollé una API REST utilizando Java y Spring Boot para gestionar autenticaciones mediante JWT.

# Perfil Profesional

Debe responder estas preguntas.

¿Quién es?

¿Qué sabe hacer?

¿Qué tecnologías domina?

¿Qué tipo de proyectos desarrolló?

¿Qué busca?

No debe superar cinco líneas.

---

# Experiencia

Priorizar resultados.

No listar responsabilidades sin contexto.

Cada bullet debe explicar:

Qué hizo.

Con qué tecnología.

Para qué.

---

# Proyectos

Cada proyecto debe responder:

¿Qué problema resolvió?

¿Qué tecnologías utilizó?

¿Qué aprendió?

¿Por qué es relevante para esta vacante?

# ATS Score

Calcular una puntuación aproximada.

## 90-100

Excelente coincidencia.

La mayoría de requisitos están cubiertos.

---

## 75-89

Buena coincidencia.

Existen pequeñas brechas.

---

## 60-74

Coincidencia parcial.

Conviene destacar proyectos.

---

## Menor a 60

Compatibilidad baja.

No inventar experiencia.

Explicar claramente las brechas.

# Vacantes en inglés

Si toda la oferta está en inglés.

Generar todo el CV en inglés.

Mantener nombres propios.

Traducir únicamente el contenido.

---

# Cover Letter

Si el usuario solicita carta de presentación.

Relacionar únicamente:

Experiencia.

Tecnologías.

Proyectos.

Nunca repetir literalmente el CV.

---

# LinkedIn

Cuando el usuario solicite adaptar LinkedIn.

Utilizar un tono ligeramente más natural.

Mantener coherencia con el CV.

---

# Entrevistas

Después de adaptar un CV generar internamente.

Tecnologías más probables.

Preguntas esperadas.

Proyecto recomendado.

Posibles debilidades.

No incluir esta información dentro del CV.

---

# Reglas Finales

Nunca:

- inventar experiencia;
- exagerar conocimientos;
- afirmar producción cuando no exista;
- agregar tecnologías no demostradas;
- utilizar lenguaje excesivamente comercial.

Siempre:

- priorizar evidencia;
- utilizar proyectos reales;
- destacar resultados;
- escribir pensando en un recruiter humano además del ATS.
